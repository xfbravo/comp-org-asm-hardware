# 下板准备说明

## 当前目标

当前还没有确定开发板型号，因此工程只完成板卡无关的准备工作：板级顶层、显示调试接口、系统级仿真入口和约束模板。后续拿到具体板卡后，只需要补齐引脚约束、外设极性和必要的时钟配置。

## 板级顶层

`src/board_top.v` 是为下板准备的顶层封装。它实例化 `cpu_core`，并把 CPU 的关键调试状态映射到 LED 和七段数码管上。

当前 Vivado 工程仍默认使用 `cpu_core` 作为 Design Sources 顶层，以保持现有 CPU 仿真和综合入口稳定。真正准备下板时，需要在 Vivado 中将 Design Sources 的顶层切换为 `board_top`，再补齐板级约束并运行综合实现。

顶层端口包括：

- `clk`：板载时钟输入
- `rst_n`：低有效复位输入
- `switches[15:0]`：拨码开关输入
- `leds[15:0]`：LED 输出
- `seg_an[7:0]`：七段数码管位选输出
- `seg[7:0]`：七段数码管段选输出
- `halted`：CPU 执行到 `ecall` 后拉高

拨码开关低三位用于选择七段数码管显示内容：

- `000`：当前 PC
- `001`：写回阶段 PC
- `010`：写回使能和目的寄存器号
- `011`：写回数据
- `100`：停止状态

## 系统级仿真

`sim/tb_board_top.v` 用于验证板级顶层的基础连线。它会运行与 CPU 自检相同的程序，并检查：

- `board_top` 能正常执行到 `halted`
- `leds[15]` 能反映 `halted`
- 拨码开关选择的显示数据与内部调试信号一致
- 七段数码管扫描输出不是无效值

通过时会输出：

```text
BOARD TOP TEST PASSED
```

## MMIO 地址规划

后续若需要把汇编程序、外设接口控制器和 CPU 集成，建议预留以下地址空间。当前 `board_top` 还没有真正接入 MMIO 总线，这张表用于后续系统集成时保持软件和硬件接口一致。

| 地址 | 名称 | 访问方式 | 用途 |
| --- | --- | --- | --- |
| `0x4000_0000` | `LED_DATA` | 读写 | LED 输出寄存器 |
| `0x4000_0004` | `SWITCH_DATA` | 只读 | 拨码开关输入寄存器 |
| `0x4000_0010` | `SEG7_DATA` | 读写 | 七段数码管显示数据 |
| `0x4000_0020` | `UART_TX_DATA` | 只写 | UART 发送数据 |
| `0x4000_0024` | `UART_RX_DATA` | 只读 | UART 接收数据 |
| `0x4000_0028` | `UART_STATUS` | 只读 | UART 状态，建议 bit0 表示可发送，bit1 表示已接收 |

## 拿到开发板后的待办

拿到具体开发板型号后，需要继续完成：

- 根据原理图补齐 `constraints/board_template.xdc`
- 确认复位按键是高有效还是低有效
- 确认 LED 和七段数码管是高亮还是低亮
- 确认板载时钟频率并调整 `create_clock`
- 若要使用 UART，补充 `uart_rx`、`uart_tx` 顶层端口和对应约束
- 若要使用 ILA，选择 `pc_current`、`debug_wb_pc`、`debug_wb_rd`、`debug_wb_data`、`halted` 作为优先探针
